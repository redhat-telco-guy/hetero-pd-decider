Hetero-PD Decider Lab

How the plugin decides, what it is worth, and a place to test it live.

Four stages, for every request

The router has already picked the answering card (decode). Your plugin decides who reads the prompt first. Keep: the answering card reads it itself. Move: another card (prefill) reads it and hands the result over. Stock llm-d's size rule gives the first answer; your plugin overrules it only when the other path is clearly cheaper. Pick a situation or change any value, and every stage recalculates.

        Router mode now:—

        With your plugin

        hetero-pd-decider, auto

        • Starts from stock's answer for every request.
        • Prices keeping and moving with live load, card speeds and network.
        • Overrules stock, either way, only when the other path is at least 25% cheaper.

        Without your plugin

        stock llm-d, prefix-based rule

        • Moves a request when it has 1,024 or more new tokens.
        • Ignores card speed, load, network and deadline.
        • This is the baseline to beat.

        How to compare the two

        1. Pick Without your plugin. Wait for the router to show Ready (about 30 seconds).
        2. On the Traffic tab, start a run, for example 32 chat users and 0.5 documents per second for 3 minutes.
        3. When it finishes, come back, pick With your plugin, and run the same settings again.
        4. Compare the two rows in Runs so far. Smoother chat (lower word gap) and faster documents mean the plugin is helping.

        Switching restarts the router, so stop any running traffic first.

          Card compatibility

          Loading…

          Two cards can hand a prompt's notes (the KV cache) to each other only when they run the same settings: model, vLLM build, attention method, KV layout. Each model server gets a compatibility key from those settings. Same key: allowed automatically. Different keys: blocked, tested automatically, and allowed only after you approve a passed test. Changes apply within about 30 seconds; the router is not restarted.

          What runs where

          Each server holds GPU cards. Above each card, read from the bottom up: the driver that lets the operating system talk to the card, the vLLM server that runs on it, and the AI model it serves. The router in front decides which card does what.
